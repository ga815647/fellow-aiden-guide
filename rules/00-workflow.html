00 Workflow｜任務路由與防截斷（SSOT）

本地 SSOT。Notion 已封存不再 runtime 讀。數字只取本目錄 01–06，不憑記憶。

每次入口

  1. 判任務：(1)新豆/v1 (2)同豆續接、杯後回饋/v2+ (3)純機制問 (4)實驗、激進、方法移植。
  2. 依任務讀本目錄必要頁；必要能力缺值不猜、不補、不稱完成。

A. 新豆/v1

  1. 讀 01（Profile Contract：阻斷欄位、原點序、payload、驗證）。
  2. 確認阻斷欄位：焙度、處理法、產地身分（單一產地至少國家，混豆可用 blend）；烘豆日缺失不阻斷。
  3. 查 Neon 回饋表同包同 key 收斂紀錄。
  4. 查 overlay（原點序：同包同key → 硬命中 → 近命中候選 → 死表冷啟；近命中只列候選不取代死表）。
  5. 未命中則讀 02（死表）、03（水量）、04（疊加：海拔/處理法/風味）、05（研磨：磨豆機換算）。
  6. 讀 06（命名、輸出、legal snap）。
  7. 組單杯＋批次完整 payload。
  8. 固定 validate_aiden_profile 通過才 create_aiden_brew_link；工具後不重算改 payload。

B. 同豆/v2+

  1. 讀 01（DB key、event_id、版本規則）、02B 等效節（本目錄 06 回饋節）。
  2. 以 bag_id＋目標水量＋濾杯＋磨豆機 查最新主版本＋梯度，取上一版完整 profile_payload。
  3. 先收自由感想；完成前不顯示預測、診斷、選項、方向；比較只對上一杯、中性對稱。
  4. 診斷矩陣只選一主變數（見 06）；幅度、合法值、步幅重讀 05/06，不憑記憶。
  5. 基於上一版改，不重冷啟；完整下版單杯＋批次 → validate → create → 新增版本列。
  6. event_id 預查＋寫後重讀，否則不稱已記錄。

C. 純機制問

只讀被問到的能力頁；不啟動 profile、不查紀錄、不寫 DB、不建 brew.link。

D. 實驗／激進／移植

  • 明講實驗／激進／指定移植才走；只說進階配方先問用哪軌。
  • 進階與基準並列，不覆蓋；實驗杯不占主版本。

失敗處理

  • 必要區段缺值：不得猜值。
  • validate 失敗：不得 create。
  • create 失敗：不得聲稱已建立。
  • DB 寫入／驗證失敗：不得聲稱已記錄。
  • CIE 或非必要工具失效：不阻斷主流程。

防截斷完成條件

新 profile 必要：阻斷欄位、overlay 結果、死表或原點 payload、水量路由、海拔疊加、處理法疊加、單杯研磨、批次研磨、磨豆機換算、命名／輸出／legal snap。 回饋版本必要：最新主版本 payload、自由感想、對上杯比較、診斷矩陣、單一 changed_variable、合法幅度／snap、DB 預查與寫後驗證。 缺任一即 FAILED。
