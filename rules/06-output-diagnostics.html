06 Output｜命名・輸出・Legal Snap・診斷（SSOT）

Legal snap（輸出前落地必要步驟）

  • ratio 與所有溫度 → 0.5 倍數；bloomRatio → {1, 1.5, 2, 2.5, 3}；bloomDuration／脈衝數／間隔 → 整數。
  • 不 snap 會被 API 擋下。

命名（固定槽位、版本號制）

  • 所有 profile 一律 豆名-水量-濾杯-磨豆機.版本：水量（300ml 省略）、濾杯（原廠省略、其餘 2 字以上代號）、磨豆機（預設 Forté BG 省略、ZP6 等寫代號）、版本（.後綴、一律帶、.1 起）。
  • token 車道不重疊：水量＝純數字、濾杯／磨豆機＝2字以上代號（槽位順序消歧）、版本＝.後綴數字（唯一用句點）。
  • 換濾杯／換磨豆機＝換原點軌、版本重起算。
  • 實驗檔另標「實驗」不占主版本。

brew.link title

  • 格式 豆名-水量-濾杯.版本 國 處理法 磨豆數 粉/水；dash-head（豆名….版本）≤16 字元。
  • 產區＝條件式可選（豆名看不出產區才加）。縮寫：國 Eth/Col/Ken/Gtm…；處理法 N/W/H/A。
  • 限 50 字元、僅英數與合法符號；| 不可用。

固定輸出三塊

  1. Overview：身分＋焙度＋產地海拔＋一句設計邏輯；方法學字眼（R²/p/snap/回歸）不進輸出；開頭必標原點層級（同包同key／overlay硬命中／死表冷啟＋近命中候選另列）。
  2. 操作表格：豆量（水量÷ratio，一位小數）／磨豆刻度（最終機刻度）／水量。
  3. 機器參數：一行 Ratio｜Bloom｜單杯脈衝｜批次脈衝；僅詢問配方時結尾問是否生成 brew.link；已明確要求建立時直接 validate → create，成功給工具連結。

診斷矩陣（v2+，一次只選一主變數）

  • 偏酸 → 先提高 EY（升溫／延長 bloom 或脈衝）→ 不夠再磨細 → 仍酸才拉稀加水。不要減水／降 ratio。
  • 偏苦 → 先降低 TDS（拉稀加水）→ 磨粗；降溫／縮短為輔。
  • 偏澀 → 磨粗 → 拉稀。
  • 偏薄／水 → 磨細 → 變濃（減水）。
  • 過萃／雜 → 磨粗 → 拉稀。
  • 不夠甜 → 拉稀（加水）、避免過萃。
  • 研磨不得細於約 300µm。
  • 偏酸若感官係數給相反方向，只能觸發同豆單變數 A/B，不得直接覆蓋本矩陣。

感官 Grilling（自由感想後、診斷前）

  • 自由感想永遠先收、零提示；完成前不亮預測／診斷／方向。
  • 一次一題、中性對稱；先找最大結構性失敗點（結構性失敗 ＞ 豆子沒發揮 ＞ 個人口味）。
  • 結束後一次亮出：預期結構 → 實際杯感 → 最大失敗點 → 次級訊號 → 理由 → 交診斷矩陣。

MCP 注意

  • 同名重試會撞「名稱已存在」（share 失敗時 profile 可能已落地）；換新標題重生，孤兒請從 Aiden app 刪。
  • 失敗（[no_brewer]＝未綁機）→ 如實說，不自編連結。

防腦補紅線

  • brew.link 只能由工具產生。
  • 不在庫的豆不補豆款／風味／微米；缺欄位標（無資料）。
  • 焙度／研磨／磨豆刻度一律查表，不插值估算。
  • 換算是估算（±1 步級）；跨機對照信方向、別當絕對值。
