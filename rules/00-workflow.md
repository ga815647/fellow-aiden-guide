# 00 Workflow｜任務路由與防截斷（SSOT）

> Git SSOT。沖煮數字只取本目錄 01–06；購豆判準取 07。Notion 僅供歷史／研究查證，不作現行規則來源。

## 每次入口
1. 先判意圖：(1)選豆／值得買評估 (2)購物車與免運搭配 (3)新豆沖煮/v1 (4)同豆續接、杯後回饋/v2+ (5)純機制問 (6)實驗、激進、方法移植。
2. 依任務讀本目錄必要頁；必要能力缺值不猜、不補、不稱完成。
3. 選豆／購物走 E；提到豆名不等於要沖煮。混合任務按使用者要求分段處理，只有沖煮部分使用 01–06 的輸入門檻與三塊輸出。

## 工具路由與資料權責
| 任務／資料 | 入口 | 使用原則 |
| --- | --- | --- |
| 現行規則與版本 | Git；公開指南為建置副本 | 沿用任務固定版本，只讀必要能力；不把日常回饋寫成規則 |
| 同包回饋、配方版本、海拔與 overlay | Neon 的已知專案與業務表 | 依 01 查寫；不能查不當作查無紀錄 |
| 商品、規格、現價、供貨、運費 | 店家原始頁／實際購物車 | 每次購買重新核對；依 07 操作 |
| 配方合法性／建立連結 | Aiden MCP | validate 不寫入；明確要求建立才 create |
| 舊研究與原始歷史 | Notion／archive | 只有查證歷史需要才讀，不作日常數字來源 |

CIE 已退出 Aiden 現行工作流程，不呼叫、不寫入、不列為前置條件；歷史文件或可見工具不會重新啟用它。相同能力有多個連線入口時選定一個，不重複發出寫入。非必要工具失效只說明相關限制，不阻斷獨立任務。

## A. 新豆/v1
1. 讀 01（Profile Contract：阻斷欄位、原點序、payload、驗證）。
2. 確認阻斷欄位：焙度、處理法、產地身分（單一產地至少國家，混豆可用 blend）；烘豆日缺失不阻斷。
3. 查 Neon 回饋表同包同 key 收斂紀錄。
4. 查 overlay（原點序：同包同key → 硬命中 → 近命中候選 → 死表冷啟；近命中只列候選不取代死表）。
5. 未命中則讀 02（死表）、03（水量）、04（疊加：海拔/處理法/風味）、05（研磨：磨豆機換算）。
6. 讀 06（命名、輸出、legal snap）。
7. 組單杯＋批次完整 payload。
8. 僅問配方時交付配方；明確要求建立連結時，以同份 payload 固定 `validate_aiden_profile` 通過才 `create_aiden_brew_link`，不再重複詢問；僅驗證不 create，工具後不重算改 payload。

## B. 同豆/v2+
1. 讀 01（DB key、event_id、版本規則）、02B 等效節（本目錄 06 回饋節）。
2. 以 `bag_id＋目標水量＋濾杯＋磨豆機` 查最新主版本＋梯度，取上一版完整 profile_payload。
3. 先收自由感想；完成前不顯示預測、診斷、選項、方向；比較只對上一杯、中性對稱。
4. 診斷矩陣只選一主變數（見 06）；幅度、合法值、步幅重讀 05/06，不憑記憶。
5. 基於上一版改，不重冷啟；完成下版單杯＋批次 payload。要求建立連結時 validate → create；僅需配方／驗證不 create。已要求記錄時依 01 新增版本列，未建連結可留空。
6. event_id 預查＋寫後重讀，否則不稱已記錄。

## C. 純機制問
只讀被問到的能力頁；不啟動 profile、不查紀錄、不寫 DB、不建 brew.link。

## D. 實驗／激進／移植
- 明講實驗／激進／指定移植才走；只說進階配方先問用哪軌。
- 進階與基準並列，不覆蓋；實驗杯不占主版本。

## E. 選豆／購物車
1. 讀 07；選豆缺焙度或處理法可標未知，不套用沖煮阻斷欄位。
2. 查可購規格、價格、批次證據與使用時機，分開呈現購買吸引力與證據充分程度。
3. 已知預算、用途、購買量與現有購物車直接沿用；會影響決策而無法取得的限制才問，不要求先建立口味偏好。
4. 提出適合本次用途的候選，比較少買含運與加購免運的實付和重量，不為門檻買過量。
5. 使用者明確要求加入時才操作；「推薦並加入購物車、湊免運」已包含這個授權。保留原有商品，操作後讀回實際車內規格、數量與金額。
6. 僅交付建議清單時不稱已加入；加入結果不明先查證，不盲目重加。最後由使用者確認訂單與付款。
7. 現有工具不支援購物車時交付可操作清單與限制，不假稱購物車功能已驗證。推薦、車內商品不寫成持有豆包或實飲回饋。

## 失敗處理
- 必要區段缺值：不得猜值。
- validate 失敗：不得 create。
- create 失敗：不得聲稱已建立。
- DB 寫入／驗證失敗：不得聲稱已記錄。
- 建立／分享結果不明：先核對既有結果；無法查證時回報，不以換名重建充當復原。
- 購物資料或加入結果不明：回到原始頁／購物車核對；查不到不等於售完，不宣稱已加入。

## 防截斷完成條件
新 profile 必要：阻斷欄位、overlay 結果、死表或原點 payload、水量路由、海拔疊加、處理法疊加、單杯研磨、批次研磨、磨豆機換算、命名／輸出／legal snap。
回饋版本必要：最新主版本 payload、自由感想、對上杯比較、診斷矩陣、單一 changed_variable、合法幅度／snap、DB 預查與寫後驗證。
沖煮必要項缺任一即 FAILED。選豆／購物的必要項與完成狀態依 07，不要求購物任務取得配方能力。
